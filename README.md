# Blockchain Ticketing System — نسخة كاملة محدّثة

مبني حسب آخر نسخة من البحث (Proposal_edit_5): تذاكر NFT (ERC-721) + دفع بستيبل كوين (ERC-20) + **حد إعادة بيع مفروض بالعقد الذكي (Resale Price Cap)**.

## الجديد بهذي النسخة
- **`listForResale` / `buyResaleTicket`**: المالك يعرض تذكرته للبيع، والعقد الذكي **يرفض تلقائياً** أي محاولة بيع أعلى من الحد اللي حدده المنظّم وقت إنشاء الفعالية — حتى لو تلاعب أحد بالواجهة الأمامية، الحماية بالعقد نفسه.
- صفحة **"سوق إعادة البيع"** جديدة بالفرونت إند.
- **إيميل التذكرة يحتوي تفاصيل NFT كاملة** (رقم Token ID، عنوان العقد، رابط مباشر لمشاهدتها على Etherscan) مو بس صورة QR.
- سهم رجوع (⟵) شغّال بكل صفحات التطبيق، وشريط تنقّل سفلي بستايل تطبيق حقيقي على الموبايل.

## هيكل المشروع
```
contracts/            العقود الذكية (Solidity)
scripts/deploy.js      سكربت النشر
test/                    اختبارات Hardhat
frontend/                 الواجهة (HTML/CSS/JS + Web3.js) — بدون أي أداة بناء
backend/                   API + Indexer (Node/Express/PostgreSQL)
```

## ١) تشغيل العقود
```bash
npm install
cp .env.example .env   # عبّي SEPOLIA_RPC_URL و PRIVATE_KEY
npx hardhat test
npm run deploy:sepolia
```
احفظ العناوين الأربعة الظاهرة بالنهاية.

## ٢) الفرونت إند
افتح `frontend/js/config.js` وحط عناوين العقود. شغّل بسيرفر محلي (**ليس** فتح مباشر بالمتصفح):
```bash
cd frontend
python3 -m http.server 8080
```
افتح `http://localhost:8080`.

## ٣) الباك إند (اختياري، لكن يسرّع الموقع كثير + يفعّل الإيميل)
```bash
cd backend
cp .env.example .env   # عبّي DATABASE_URL + عناوين العقود + بيانات SMTP (اختياري)
npm install
npm run db:init
npm run dev
```

## ⚠️ Metadata حقيقية للـ NFT (تحديث جديد — يتطلب إعادة نشر ٣ عقود)
`TicketNFT` الآن يولّد Metadata حقيقية (اسم، وصف، خصائص) بصيغة JSON مُرمّزة Base64 **داخل العقد نفسه** — بدون IPFS ولا أي سيرفر خارجي. هذا يعني `tokenURI(tokenId)` يرجّع بيانات فعلية بدل فارغة، وتقدر المحافظ/Etherscan تعرضها مباشرة.

**لازم تعرف:** بما إن `TicketNFT` صار يحتاج عنوان `EventRegistry` بالـ constructor (لقراءة اسم الفعالية)، و`TicketMarketplace` فيه `immutable ticketNFT` ما يتغيّر بعد النشر — **لازم تعيد نشر ٣ عقود مرتبطة مع بعض**: `EventRegistry` → `TicketNFT` → `TicketMarketplace`، بنفس ترتيب `scripts/deploy.js` بالضبط. `MockUSDC` وحده ما يحتاج إعادة نشر.

## آلية حد إعادة البيع (Resale Cap) — أهم إضافة بهذي النسخة
1. المنظّم وقت إنشاء الفعالية يحدد `resaleCapPercent` (مثال: `110` = يُسمح بالبيع حتى 10% زيادة، `100` = بدون أي ربح، `0` = منع إعادة البيع كلياً).
2. صاحب التذكرة يستدعي `listForResale(tokenId, price)` بعقد `TicketNFT`.
3. أي شخص يحاول الشراء عبر `buyResaleTicket(tokenId)` بعقد `TicketMarketplace` — **العقد نفسه** يتحقق من `registry.getMaxResalePrice(eventId)` قبل تنفيذ أي تحويل مالي، ويرفض المعاملة (`revert`) لو تجاوز السعر الحد المسموح.
4. هذا يعني الحماية **ليست واجهة فقط** — حتى لو استدعى أحد العقد مباشرة بدون المرور بالموقع، الحد يبقى مطبّق.

## آلية إرسال NFT بالإيميل
بعد كل عملية شراء ناجحة (أساسي أو إعادة بيع)، لو المستخدم مسجّل إيميله بالملف الشخصي والباك إند شغّال ومضبوط بـ SMTP:
- يُرسل إيميل يحتوي: رقم Token ID، عنوان عقد `TicketNFT`، رابط مباشر لمشاهدة الـ NFT على Etherscan (Sepolia)، وصورة QR للتحقق عند البوابة.
- لو SMTP مو مضبوط، التطبيق يشتغل عادي بدون ما يتعطل — بس المستخدم ما يستلم إيميل، ويعتمد على QR داخل التطبيق (قابل للتنزيل كصورة).

## ملاحظة أمنية (لخصها بمناقشة البحث)
ترميز `tokenId` وحده بـ QR بسيط لكنه ليس آمناً بالكامل — التحسين المستقبلي المقترح: توقيع EIP-712 بدل رقم مباشر.
